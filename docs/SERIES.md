## 1. 世界观和不可改变的边界

玩家和小芽是归光营地的住户；现实里完成一件支线，带回一点光与一段可安放的记忆。小芽是守灯伙伴，保留当前称呼；木木师傅负责木作与荣誉陈列的工艺叙事，不做任务审核员。玩家缺席时营地不会衰败，小芽也不以负面情绪催债。此为选定A后的叙事决定，依据第三轮方案的 D1/D5/D7 与用户授权；不是已上线剧情。

第三轮其余决定：现有核心场所始终可达；未来苗圃/林间工坊/静水湖/归光山坡暂按 Lv.3/5/7/9 规划，跨季保留已解锁区域与小家。湖区先承担安静回顾，不锁定专注钟。第四轮系列不能依赖这些尚未实现的区域才能完成或领奖。

### 限时的具体含义

“限时”限制本季板上的新接取窗口，不制造已接任务作废或惩罚。赛季结束后，旧edition归档、原展示进度和所得荣誉保留；已接任务按接取时锁定的规则完成，照旧结算。未接的旧edition不再推荐，下季发布同family的新variant，错过仍可获得同一章及其全部阶位。

跨季完成旧edition：完成记录的 `completedSeasonId` 按实际完成日期归属新季；旧editionId与seasonId仍留作来源。它不同时算两季。同一个目标仅改文字或换edition不能成为新的distinct goal。下季变体必须有真实的事件差别，由作者赋予新canonicalGoalId；不要求恢复已经完成过的任务再领一份光。

月章只是组织与发布节奏，不设月末章清零。没有一天倒计时、最后机会弹窗、缺勤倒退或付费补票。

### 1st 与家具首次铭牌

1st的“首次”是人生语义，不是“系统第一次见到这个qid”。用户诚实确认；已有经历不能因换设备或换季变成新首次。历史首次可在证据明确时补入荣誉记录，**不会补发任务XP/光或触发购家具**。已有家具铭牌仍只由实际购买绑定，不因获得章被消费或自动占用。

首次事件条目与章是两个关联对象：条目永久保留“哪一次首次”，章记录这条主题线后来达到的最高荣誉。后续深化节点不能要求重复第一次；不适合长期深化的孤立首次，只放入已有相关family，不为每个微小首次制造一枚独立章。

## 4. 作者如何直接开始填第一批

### 推荐首季编辑预算（内容尚空）

N=8个长期family，每种模板一个；这是首批策划上限，不是每赛季再发八枚。准备**19条独立事件任务**：七个family各1个可达m1的核心事件，组合family的m1固定两个组、各1个独立事件（合计9条），另选五个适合深入的family，各2个进阶事件接m2/m3（10条）。剩余三个family首季只开放素刻路线，明确“后续主题待续”，不展示锁定的镀彩倒计时。

19是作者工作量建议，不是玩家必须做满的清单。m4–m6留给后续赛季，先写成长方向和证据要求即可，具体任务文案保持空。累计类m1可由一条有明确已结算数量的事件支持；组合类m1必须两条不同证据，不能让一个完成填两个组。若组合改成三组，或某个其他m1需要更多独立任务，应调减其他首季内容或重算预算，不能悄悄把19变成30。

### 填写次序

1. 先选一个模板，写family主题名和一句“这条线怎样算走得更远”；确认它能维持至少三个阶段，而不是为了凑章。
2. 分配稳定的familyId、seriesId、revision、badgeId。id用英文小写短横线，永久不复用；显示名由你写，改名不换id。seasonal另填seasonId/variantId，其余clock保持lifetime。
3. 在原任务目录写任务内容并定cat/diff/type/tier。首批优先once；total只用于事件成果量。阶段模板使用既有chain/stage；不得在两个文件各维护一份前置。
4. 为每个真实完成目标分配canonicalGoalId；为每条任务指定唯一primaryFamilyId。first/探索/创造/复盘补相应证据槽。一个现实成果不能拆成两个ID骗取两个独立目标。
5. 从m1开始填 `criterion` 的任务候选、阈值和必要字段。六个milestone槽是长期计划，可以留未发布槽空；**只把已填完整、前置可达的槽加入edition的发布清单**（未来字段 `publishedMilestoneIds`，本轮骨架预留）。
6. 指定每阶引用哪些已命名milestone。已接规则通过revision锁定，发布清单与任务引用一起审核。m1=素刻；m1–m3=嵌纹；m1–m6=镀彩；同时检查§5通用门槛。若只有三个任务，则只写前三个槽，不凭空写后三个任务。
7. 写玩家可读的完成判定句：动作/成果范围、必要数量、是否可重复、证据如何自述、怎样算独立。不要要求实现尚不存在的线上认证、地图点击或付费道具。
8. 最后写NPC缘由和展示摘要。NPC文本是你的文案，不由程序填入；`guideNpcId`只从已存在或已约定的角色选，小芽/木木不会变成奖励审批人。

### 内容发布前的检查规则（未来验证器规范，本轮不实现）

draft不得进入运行目录；id唯一且引用存在；cat/diff来自原字典；task绑定一个主family；数值阈值为正有限数且单位一致；前置无环且只指向本family较早槽；`staged`前置与CHAINS一致；未填任务不得用空字符串当通配符；空数组不得按“全部满足”发章。一个m1至少有一个真实完成目标；组合至少两个组且存在不复用证据的可行解。

每个发布edition的 `publishedMilestoneIds` 必须非空且只含填完整的槽。后续章门槛允许未开放，但文案不得宣称当前可完成。任务不得设置“获得章”的完成条件，避免循环。难度更高不替代缺失前序，也不新增XP。

## 5. 蚀刻章映射、升级树与获取曲线

### 一条长期主题线，一枚章

`familyId → badgeId` 一对一；family里可跨多个series edition、季度变体、月章和任务节点。series是一期内容编排，milestone是荣誉判定节点，badge是这个family的收藏对象。**不是每条任务一章，也不是每季一章。** 一次升阶更新同一条图鉴记录，保留之前获得时间和证据，不在总枚数里加一。

八种类别不等于八种自动生成图案；首批预算恰好各一个family，所以第五轮暂定N=8。只有用户实际填好并确认这八个主题的名称、意义和成长方向，才能设计八枚有各自构图的章；不能用类别图标换色凑数。

```text
一个family / 一枚章
m1 ── 素刻
 └ m2 ─ m3 ── 嵌纹（还需3个独立目标，其中≥1项B或以上）
              └ m4 ─ m5 ─ m6 ── 镀彩
                 （累计≥6个独立目标、≥2项A或以上、完成证据覆盖≥3个不同赛季）
```

| 阶位 | 全部必须满足的条件 | 难度关系与时间含义 |
|---|---|---|
| 素刻 rank1 | m1已达成；至少1个已完成独立目标；证据有可确定的完成赛季 | E–S均可入门；不是所有E任务自动送章，要属于已发布family的m1 |
| 嵌纹 rank2 | m1/m2/m3全部达成；全family至少3个独立目标；其中至少1个B/A/S | B是最低进阶质量门槛，不按XP总额兑换；首季可达，但三个相似E任务不够 |
| 镀彩 rank3 | m1–m6全达成；至少6个独立目标；其中至少2个不同目标为A/S；合格证据分布在至少3个不同赛季 | S不强制，一条S也不能抵两条A；三季不必连续。最早第三个参与季可达，正常从开季参与约半年以上，具体取决于事件完成时间 |

所有条件是累计AND，难度从**完成时任务快照**读取；不得把任务日后改成A后给旧完成升级。`distinctGoalsMin`与“高难度目标数”按canonicalGoalId去重；同一条高难度记录可同时满足数量和难度要求，不能计成两个目标。三季按**真实完成日期归属的赛季**去重，非登录、接取、编辑笔记或光结算日期。

同一章规则对八类一致；类型决定milestone怎样判断，而不改变阶数。连续累计可以一次跨过多个数量阈值，但仅有一个目标仍只能拿素刻；一次历史导入可直接显示已经满足的最高阶，不强制连续点击领取，历史中间阶也记为同次恢复，不多发奖励。

### 为什么第一季不会人手镀彩

第一季的新family有效证据从该family发布季起计，不能把发行前无映射的旧记录随意归入三个季。首季最多只有一个有效完成季，且只开放m1–m3，所以镀彩数量为0。第二个参与季可推进高阶目标，第三个及以后的非连续参与季才有资格终阶。这是长期荣誉条件，不要求玩家每季到场；错过任一季可在之后补足，不降级、不卖补票。

历史首次可保留真实发生日期与“补录”标识，但它不凭未经确认的日期满足跨季门槛；如何补录见§8。未来如果要认可发行前的旧系列，必须有公开、确定的迁移映射，不能静默放松首季预算。

### 发放预算（策划估算，不冒充真实留存数据）

| 玩家路径 | 首季可能获得的独立章 / 阶位 | 推导 |
|---|---|---|
| 轻量尝试 | 1–3枚素刻 | 选择少数主题，各达m1；不要求刷全五域 |
| 正常游玩并认真完成 | 3–5枚，其中1–2枚可到嵌纹，其余素刻 | 约8–12个符合主题的独立事件，集中完成一两条线；如两个family各3目标、另两family各1目标，则8目标支持4枚、2枚有嵌纹资格，仍需m规则和B条件 |
| 深度首季玩家 | 上限8枚，最多5枚嵌纹，0枚镀彩 | 首批仅8family，其中五个开放m1–m3、三个只开m1；19个事件全部完成也受阶位发布范围约束 |
| 后续一个赛季 | 目标新增0–2枚，多数回报为旧章升级 | 每季最多新增2个family，其他是现有family变体；不是每季刷新八枚清单 |

这不是给玩家的领取配额：达到声明条件必须授予，不能在第6枚时临时拒发。“最多”由内容目录和升阶条件形成，不能靠隐藏限额。若作者改了首季任务数、family数、主归属或高阶开放范围，必须重算此表再发布。

预算防通胀有三层：每个完成只给一个主family荣誉证据；每个family永久只有一枚章；全部获得/升级额外XP=0、光=0。章没有数值属性、不出售、不合成、不交易、不用光升级。长期已有章很多是人生积累，不以销毁旧章来制造稀缺。

## 6. 进度判定与去重协议

以下是未来 `game/` 纯逻辑实现的合同，本轮只有声明，没有求值器或发放函数。

1. `store.complete`先按原流程完成结算，得到一条稳定completion记录；系列只能消费完成结果。checkIn/logUnits仅作进度预览，不直接产生章；家具互动、购买、地图点击与导入都不调用奖励结算。
2. 完成记录锁定 taskRevision、DIFF、cat、canonicalGoalId、primaryFamilyId与seriesRevision。一个记录只属于一个主family；跨类标签可用于浏览，不给第二枚章累计证据。1st永久事件条目可作为附属记忆展示，不因此再造第二枚章。
3. 对 completionId 去重，再按 canonicalGoalId 计算独立目标数。同一canonicalGoalId多次完成只贡献一次荣誉目标；累计量也只取其中最大一份合格settled units，不重复叠加。一个goal用于难度和跨季的归属固定为其首次合格完成快照；后续重复记录增加该goal的最大数量，也不增加独立目标、难度或完成季。不同goal若共享evidenceId，优先最早合格完成（同日按持久completionId排序）用于荣誉，其余只保留事实记录；不得借重复证据绕过唯一主family。不同单位不能比较或相加。原人生累计面板继续照原规则统计，章的保守去重不回写其数值。`evidenceId`标识用户确认的同一个实际成果，防止同一成果挂在两个任务下；多个日志汇成同一total任务仍是一个完成目标。现有旧记录没有这个保证，见迁移限制。
4. 同family范围内聚合：数量条件用合格记录的settled units；组合为每组分配不同证据（采用确定性的匹配，而非贪心第一条导致误判）；探索按placeKey，创造按workId，复盘按被回看的completionId。所有读取只接受声明的task候选与主family，不扫描任何记录就计入。
5. 检查前置，再求各milestone是否达成；同时求章公共门槛。保存“最高已授阶位＋获得历史＋证据引用”，重复刷新/重复导入不得再增加收藏数量。没有负向倒退、倒扣或再次通知。
6. 内容编辑不重新解释已获得荣誉；新版本为新接任务启用，已接按锁定版本完成。纠错/用户恢复另一份备份属于数据恢复，不假装是系统没收荣誉；正常玩法的缺席与任务放弃不影响已获章。

### 各种容易算错的情况

| 输入情况 | 必须得到的结果 |
|---|---|
| 当天三次记录或同一完成按钮重复调用 | 仍按原微光规则；荣誉只认一次完成ID，不增发XP/光 |
| total任务尚未完成，面板已有累计量 | 可预览未结算进度；不得拿这部分发章。不能直接复用包含active的lifeMetrics作为发章输入 |
| 一条完成同时看起来像“第一次＋探索＋创造” | 作者预先指定的一个primary family获得章证据，其余只能显示标签/首次记忆条目 |
| 季节变体只改题目，仍是同一真实目标 | 维持canonicalGoalId；不增加distinct goal或把完成日期复制到新季 |
| 同一个实际成果被两条任务引用 | evidenceId相同只能用于一次荣誉计量；不会在本轮追溯改掉旧任务经济 |
| 组合两组都允许同一任务 | 必须有两条不同证据才能满足两组；一个完成不能填满两格 |
| 单次大量累计超过m1/m2/m3阈值 | 阈值可全满足，但章还要满足3个独立目标与B条件，不凭超大数值跳阶 |
| 重复编辑同一篇回顾、同一作品保存十次 | 不新增复盘来源/作品；纯编辑不再发章、XP或光 |
| 放弃了一条任务 | 不算完成证据；既有放弃记录照常在手记，章与光不扣除 |
| 赛季结束还有已接任务 | 保留按旧revision完成的资格；跨季完成只计实际完成所在一季 |
| 少一个必要字段、未映射旧任务、无可靠日期 | 显示待确认，不猜测，不发高阶；保留原任务与余额 |
| 重新导入同一份备份 | 同completionId与badge/family键幂等；不会叠加一份奖励或新章 |

作者的诚实自述是证据，不做机器判文、不要求上传照片、不要求GPS或社交认证。复盘的新任务只有在“回看并产出一个新结论”是作者明确设计的独立事件时，才可走正常任务结算；给已有完成回顾补几个字不算第二个任务。具体结论要求由作者写，不以字数、积极程度评优。

## 7. 光、铭牌、图鉴与视觉

| 系统 | 拥有什么 | 不拥有什么 |
|---|---|---|
| 光 | 原任务完成奖励＋累计微光；退款照旧 | 章不兑光、光不买章、升阶不发额外XP、NPC不代发光 |

| 蚀刻章 | family的永久荣誉身份、最高阶位、获得时间及证据索引 | 不提供buff，不建第二套角色等级、称号或技能点 |
| 图鉴 | 每章一条主条目，展开三阶历史与关联完成；1st首次事件有附属条目 | 升阶不算多一枚；不要求收藏家具或反复点地图来填空 |
| 成长手记 | 事实与原始回顾，是图鉴回看经历的来源 | 不因章未开放而把原记录隐藏或清空 |

### 图鉴入口与两击路径

默认**沿用瞭望台建筑**，在其手记视图内规划一个木质「营地印记柜」。地图点瞭望台是第一击，选印记柜是第二击；未来可将“手记/印记”作为同一场所的两个视图，不新增顶部多入口导航。章详情在柜内展开，不算新主功能入口。未得章的玩家从第一天也可查看已发布目录，不能让Lv.9山坡成为领奖门槛。

任务系列入口仍是地图任务岩壁→系列分类，最多两击到系列列表；具体任务详情是列表内操作，沿用已有接取上限。木器铺负责扩建/墙地，不迁走原功能；可以在叙事中解释木木制作陈列架，但免费自动收藏，不强迫先付光买柜子。未来山坡可展示赛季收藏回顾，不能成为第二套独立图鉴状态。

### 三阶纹样方向（没有美术产出）

| 阶位 | 材质与构图要求 | 可辨识变化 |
|---|---|---|
| 素刻 | 一枚有独特外轮廓和主符号的木刻拓印/哑金属浅刻，留明显刀痕与空白；木或金属由该主题决定 | 即使单色缩到32px，也能凭外形和主负形认出family |
| 嵌纹 | 保留该章主符号，新增与主题有关的第二层结构、嵌线或镂空；如改变层次与边缘连接方式，不能只加一圈通用边框 | 轮廓、刻深与内外关系发生一项明确变化；不靠换色认阶 |
| 镀彩 | 让该章长期主题在结构上“完成”：主纹闭合、层次汇合或出现此前缺失的关键构件；局部矿物色/薄镀面点亮，不全章高饱和 | 一眼有终点感，同时保留磨砂、木纹/锤痕和留白；不用彩虹渐变、宝石贴纸或通用皇冠 |

每个family必须有自己的物象逻辑、负形和三阶叙事。当前类别只是骨架，没有用户写出的实际主题，因此不能预先画八枚通用图标。第五轮先编号总览供逐枚审阅，再按批准结果补足N×3单张与一张陈列场景；用户逐枚确认后才实现程序化或本地渲染资产。拒绝把现有参考图直接贴进站点。

## 8. 声明结构与v3兼容方案

### 本轮文件与状态

- `app/src/data/series.js`：8个draft占位模板、空 `SERIES` 目录；每类一个，含6个长期里程碑槽、分类专用criterion与任务挂接槽。
- `app/src/data/etchings.js`：3阶公共规则、8个章draft模板、空 `ETCHINGS` 目录；每阶美术描述与assetRef均为空。
- 它们不被store/App/场景导入，不能生效或写存档。`enabled:false`和空目录是双重明确边界，不能当作已实现的发章系统。

| 字段 | 填法与含义 |
|---|---|
| templateKey | 固定8类之一；只是模板定位，不用作正式seriesId |
| id / familyId / badgeId / revision | 正式内容稳定标识；revision正整数，每次发布条件改变递增，旧版保留 |
| familyReleasedSeasonId | family首次发行季；所有edition保持一致，只统计该季及以后有效证据参与升阶，首次事实条目可另保留更早发生日 |
| title / premise / completionExplanation | 作者填写名称、缘由与可判定规则；空字符串就是未完成内容 |
| cats | 原CATS键的数组，不影响既有XP归属；真正结算依任务cat |
| clock | seasonal引用现有season时钟与variant；其余lifetime；close/accepted/progressCarry是§3的固定策略 |
| publishedMilestoneIds | 当前edition实际开放且填全的milestone；不能把所有空槽自动发布 |
| milestoneSlots | m1…m6结构槽；正式id填写后稳定；title/description由作者写；prerequisiteSlots组成无环图 |
| criterion | 明确允许的8种操作之一；taskIds限定候选；canonicalGoalIds限定独立目标，target为正数；不运行字符串表达式 |
| staged chainId/stage | 与CHAINS及任务chain/stage一致；不得在此发明另一条解锁链 |
| first firstKey/phase | m1为first，后续followthrough；同firstKey首次终身唯一；target只能为1（每个节点对应明确目标） |
| cumulative metric/unit/target | metric来自METRICS，unit一致；target为该里程碑从family起点累计的阈值，单调递增 |
| combination groups | 2–3组，组内是候选任务达到target，组间AND；必须能分配不同证据 |
| exploration placeKeys | 非GPS的抽象地点键；target为不同地点数，作者先定义“不同”的粒度 |
| creation workKind | 作者定义作品类型与“完成”界线；target为独立作品数；workId来自真实完成自述，不是图片URL |
| reflection sourceTaskIds | 可回看的原记录任务范围；target为不同来源记录数；自述已完成所需复盘，不按字数判定，minimumTextLength固定null |
| taskBindingSlot | 将来附加到任务声明的系列归属示例，不复制任务标题、价格、diff；milestoneSlots为可贡献槽位 |
| proofPolicy | 仅settled completion、唯一主family、三种去重键、旧记录需明确映射；不是网络验真 |
| badge tiers / milestoneIds | 依plain/inlaid/gilded绑定对应已填槽，另叠加公共门槛；不能只填写图片就算已得章 |
| art | concept/silhouette/motif/relief/material/finish/accent/assetRef留待第五轮；approval保持not_started |
| entry / catalog / npc | 提案定位符tasks/journal、印记柜与buddy/woodworker；不是新组件已存在的保证 |
| seriesBonus / exchange | XP与lumens固定0；不得被作者当作奖励调整口 |

各criterion的target含义：seasonal为完成目标数；staged为1（完成所指stage）；first为1；cumulative为同单位总量；combination必须等于groups.length（全部组均满足各自target）；exploration为不同placeKey数；creation为独立workId数；reflection为不同来源completionId数。taskIds与canonicalGoalIds均为显式非空允许集，按交集筛选；组合另检查组内允许集，不存在空数组代表“任意任务”的约定。组的cat可为null表示不限定领域，clock中非适用项和美术assetRef的null也按各字段明示含义处理。

在必填内容槽中，`null`表示未填写，不能解释为0、不限或已满足；`[]`表示无内容，draft不会参与判断。`minimumTextLength:null`是明确“不做字数判定”的策略字段，发布校验必须按字段语义处理。

### 兼容与迁移，不静默吞字段

1. **本轮没有迁移。** localStorage键、`version:3`导出和normalizeState不变；空模板不进入旧保存流程。当前save白名单会丢弃未认识的新字段，importData也只赋值已有顶层字段，因此绝不能提前把seriesProgress塞进当前运行时然后声称兼容。
2. 真正接入时保持v3为业务格式、给可选seriesProgress增加独立schemaVersion=1；同时改自动加载、normalizeState、importData、exportData、emptyState和resetData，缺字段旧档默认空。先自动备份原JSON，保留v1/v2旧键；迁移只增加荣誉索引，不重新调用complete/rewardCompletion/recordGlimmer。
3. 新完成使用持久随机completionId。旧done按首次迁移时的原始索引＋qid＋at＋同键出现序号生成稳定legacy ID并保存；后续使用持久ID，不能每次排序后重算。完全相同的旧记录不能直接删：旧档允许可重复任务，人工审查不明来源时宁可不追授章，也不能删其XP/手记。
4. 旧任务只有在显式迁移表提供family、canonicalGoalId与历史diff快照映射时才追认；不能把xp倒推为难度，不能拿当前可变任务定义强行冒充历史快照。旧首次和地点/作品/复盘证据缺失时由用户日后确认，只补荣誉，不补货币；原记录日期保留，未知完成季不计跨季门槛。
5. 保存所有历史任务/series版本的只读注册表，别从TASK_IDS直接移除下架任务。当前normalizeState会过滤不在TASKS的qid，必须在真正上线季节轮替前修正为可识别的历史目录/隔离保留区，并做往返测试。本轮不修改既有任务目录。
6. 图鉴保存稳定id与获得历史。暂时缺失的badge/family定义放入可往返导出的“未解析记录”，不清空荣誉；未知更高schemaVersion要提示版本不支持并保留原备份，不能当空对象覆盖。校验引用、长度、正有限数与允许字段，不执行自定义脚本。
7. 导入沿用“确认替换并先导出当前数据”，不是自动合并两设备；本地幂等由completionId、milestone复合键、badgeId保证。将来若做合并，应另立规格；本轮不承诺多设备去重或云端身份。
8. 老版应用不能理解新字段，向老版回滚会丢系列扩展。因此应明确标注最低支持的series schema，回滚前导出完整新档，旧应用不得覆盖唯一备份；不能声称任意旧版本可无损读新章。新实现的迁移验收必须覆盖此边界。

## 10. 第五轮的启用条件与交接

本轮采用的技术与经济决定可以开始写第一批内容；**美术不是根据八个空类别自动开画**。启用第五轮须有：①本稿映射、三阶与入口获得用户定稿；②用户填好首批N个family的名称、主题意义和核心物象方向；③锁定每枚章的三阶成长含义。默认N=8；若内容只准备好部分，可明确缩为已定稿的N，不用空白章凑数。

流程为编号总览→逐枚反馈→N×3单张与陈列场景→用户逐枚确认→分批实现并截图。不得把本轮“其余抉择由你确定”当作尚未看到图片的逐枚视觉批准。图鉴界面、3D陈列资产、系列求值器和迁移都属于后续实现轮次。
