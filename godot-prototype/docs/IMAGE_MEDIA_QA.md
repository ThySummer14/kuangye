# v7.5 图文候选：验证与剩余边界

此候选基于原始Godot v7.4。稳定站保留v7.4；候选源码、Web导出和证据单独保存在恢复包，源码提交不代表稳定站升级，不把未完成的浏览器集成说成已通过。

## 已验证

- 55项图片规范化检查：实际PNG/JPEG/WebP签名，解码前20 MiB/1600万像素/最长边8192限制，坏文件与动画格式拒绝，8种JPEG方向及PNG/WebP方向处理，重编码去元数据、透明背景压暖白。
- 27项模型/迁移检查：最多4图、共享1800000字符容量、重复/移除/失败原子候选、图片作品完成、文字章证据不放宽、v3→独立v4一次迁入、旧文件保留、损坏当前文件不静默回退。
- 最终29项离线图片界面检查；此前28项原生图片界面检查包含真实桌面/375×812窗口、保存/重开、陈列与失败重试。新增4图长页的键盘缩高是代理检查，不能说成手机输入法通过。
- 最终19项离线导出检查；此前20项原生导出检查包含1200×1600真实PNG绘制与边界。两套计数独立，不能相加。
- 20组最终离线回归通过，保留房门退出、家具、观察/文字创作、动作和章柜。另有3项打包边界与8项浏览器桥异步逻辑检查。
- 原生应用真实文件列表实际选择4张原创QA图，随后测试脚本触发生产保存按钮。重新读取存档4图字节完全一致，28.561秒，峰296 MiB。早先也实际点过选择器Cancel，未加入图片。
- 最大允许1600万像素四色PNG规范化实测1.576秒，受控进程峰188 MiB；这是单个云端样例，不是所有图或手机性能保证。

## 浏览器组件真实验收

同生产PICKER_SCRIPT在真实Chromium选择4张原创PNG/JPEG/WebP，接收到的每个字节数和SHA256均与原文件一致。又在现有Chromium的原生文件对话框实际点击Cancel，返回cancel、未加入图片。测试工具的空setFiles接口不可用，取消改用真实Cancel按钮完成。

下载使用Godot4.6.3的`godot_js_os_download_buffer`原函数体，仅用适配器代替WASM内存和字符串指针。实际收到PNG与HTML，并与生产导出器样本逐字节一致：

| 产物 | 字节数 | SHA256 |
|---|---:|---|
| PNG，1200×1600 | 48625 | 3da0cc5efc288e765f39fa6d2f3a99e4ee40b9e430884690adbb2a563de8ee44 |
| 完整HTML样本 | 7865 | d7528ac9580225911b57c99baf1c5ce6af966a312d4572420a0856990ab3b8f8 |

浏览器打开HTML后，两张内嵌JPEG尺寸正确；script元素为0；测试私语不存在；`<script>`和`<img onerror=…>`测试内容作为普通文字显示。所有测试图片和文字都是QA数据，不进入默认存档或宣传截图。

复现组件页：先以独立测试用户目录运行原生`tests/test_studio_export.gd`，再执行`python3 tools/build_media_component_fixture.py --output /path/to/component-test`并通过本机HTTP打开生成目录。此页不运行完整WASM游戏，也不测IndexedDB。

## 已修复的失败边界

1. 本地导出写入/重命名失败后清理本次临时副本；清理也失败时明确提示。包含测试私语的真实重命名失败用例无临时副本残留。
2. Godot4.6.3的Unix缓冲写入可能返回true、flush后错误码仍为0，却只保存部分字节。用独立子进程512字节文件上限复现2000字节仅写512字节。保存与导出现在在替换前重新打开临时文件比较完整字节，失败保留原文件。测试不填满磁盘，也不改全局设置。

字节回读证明OS当前可读的数据完整，不等于断电fsync保证，也不能证明浏览器异步IndexedDB提交成功。

## 未通过与待验

完整Godot Web在云端官方能力检查处停下：现有浏览器没有WebGL2；独立临时profile保留默认沙箱/图形配置后，日志仍明确`WebGL2 blocklisted`。未改变原浏览器、安全设置或GPU黑名单。该路线已停止。

因此，WASM内GDScript↔JavaScript桥、游戏内图片流程和关闭浏览器后的IndexedDB持久化仍未完成集成验收。真实手机相册选择、取消返回、中文输入法/安全区、系统下载/分享及性能也未验。原生、组件和窗口尺寸测试不能替代这些检查。

## 候选发布与手机最小验收

1. 先把恢复包内的生产`web-preview/dist`部署到单独owner-only候选地址；不得部署`tests/browser_component`或`tests/web_media_qa.gd`测试入口。稳定v7.4地址先保留。使用同一已支持的gzip引擎加载方式，核资源清单。
2. 候选站使用新地址、空白存档，与稳定站分开保存，不会读取或自动迁回原站进度。只用测试图片和测试文字。在手机候选页进入作品集，新建作品；先打开相册再取消，确认没有多图。随后选一张自己的测试图（保留原图），编辑标题，确认软键盘下关闭/保存可达。
3. 保存并完成作品，陈列到小家；退出房屋后确认正常站在镇上。关闭浏览器，再用同一地址打开，确认图、文字、家具和章记录仍在。
4. 分别下载PNG和完整HTML并实际打开。默认不应有私语；多图PNG标“作品选页”，HTML应保留全部图文。
5. 如图片/存档/下载异常，先保留页面和原始文件，记录设备、浏览器与出错步骤；不要清网站存储。

候选写独立v4文件。仅不存在v4时读v3或旧v1/v2；旧文件不变。回退旧版后新增的进度不会自动并入已有v4。HTML作品集不是完整游戏存档备份。现有Vue/Web/APK数据结构不在本轮导入范围。

依据：[Godot4.6.3下载桥](https://github.com/godotengine/godot/blob/4.6.3-stable/platform/web/js/libs/library_godot_os.js)、[FileAccessUnix](https://github.com/godotengine/godot/blob/4.6.3-stable/drivers/unix/file_access_unix.cpp)。Godot下载函数MIT许可随组件测试源保留。


## 为什么不放在稳定站的子路径

建议单独origin的owner-only候选站。已打包的引擎默认持久目录为`/userfs`；IDBFS同步会删除本地快照没有的远端项。从该代码推断，同源旧/新游戏标签并开可能发生相互覆盖，这里没有做破坏性实机复现。独立候选站避免触及稳定站存储，但不会自动迁入旧站进度，也不会把候选进度迁回。

待手机验收后若正式更新原站，应先关闭旧版标签，再由同源新版一次读取v3并另存v4；旧文件仍保留，旧版之后的新进度不会合并到已存在v4。不要把候选站的独立数据误当成原站数据。
