# 自己写一件 · 第一版产品规则

2026-09-27。入口为地图 → 任务岩壁 → 自己写一件。用户已授权本轮功能与 UI 更迭。

## 目的与流程

现成任务只能覆盖部分生活。用户可以写一件一次性小事，明确“做什么”和“怎样算完成”，选择生活领域，并可填写开始时机和第一步。保存即接下，回到对应行动卡；地图可接续。进行中可以修改，完成时确认原条件、写回顾；完成或暂放后的内容冻结，手记保留当时的标题和完成条件。需要重新尝试时另写一件，不能重新接取并改写同一条已暂放历史。

第一版只支持一次性自建任务，不提供重复打卡、自动计划或自选奖励。共用全局三个进行中名额，独立于现成任务的章节/赛季子上限。取消表单不创建任务；完成与暂放沿用 store 的现有语义和保存提示。

## 奖励边界

自建任务直接奖励为 0 XP / 0 光，不提高等级或领域称号。完成当天登记既有微光：与现成任务、打卡共用每天最多一份，累计七个有记录的日期获得 5 光，不需要连续。不新建计数器、不增加每日或每七日发放上限；反复创建和完成只能增加真实经历条数，不能重复领取当天微光。完成回顾仍可绑定下一次购买家具的铭牌，购买价格不变。

## 数据与兼容

v3 新增可选 `customTasks` 声明数组；每件任务使用 `personal-<UUID>` ID。声明经 `game/personal-tasks.js` 白名单清洗，固定一次性、固定 personal 类型，导入不能设置难度或奖励。`active/done/abandoned` 沿用 qid，开始安排沿用 plan；标题 60 字、完成条件 240 字。定义保留，不随完成或暂放删除，因此手记、报告与家具铭牌仍能解析。

本地读取与导入共用清洗路径。缺失自建任务定义、重复 ID、非法声明会拒绝，而不是静默删除对应经历；无 `customTasks` 的旧 v3/v2/v1 正常读取。自建完成记录的 XP 清洗为零，旧档无 home 时的光折算也排除自建 XP。备份继续包含完整 state。含自建任务的备份需用支持本功能的版本恢复；旧版导入会以未知任务拒绝，保留原文件。

## 岩壁结构

首屏明确“自己写一件”；有进行中任务才显示行动区。发现区直接展示已有四个生活方向，成长线为一个入口；时间/场景细筛选折叠，搜索和完整任务库保留。所有入口仍在任务岩壁内，地图是唯一主入口。没有新素材或依赖。

## 验证

60 项测试通过；构建通过，保留已有 three 分包体积警告。1280 / 375 浏览器完成创建、编辑、地图、刷新、结算、手记、备份往返、满额阻止、暂放和现成内容发现；无 pageerror 或横向溢出。具体证据见 `output/personal-tasks-final-test.txt`、`output/personal-tasks-final-build.txt` 和 `output/playwright/personal-tasks-verification.txt`。未重复原生、日夜或发布矩阵。
