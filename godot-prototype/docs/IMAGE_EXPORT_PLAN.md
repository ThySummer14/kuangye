# 图文作品与本地导出：最小技术方案

基线：原始 Godot v7.4，公开提交 `3f1e4a314aaefd1d0a7821eee6867742d043b15b`。本文件为下一增量方案。本轮功能已接入并完成原生和浏览器文件组件检查；完整WASM游戏集成与真实手机仍待验，见IMAGE_MEDIA_QA.md。已有章柜/门槛/小芽动作保持稳定；不接新云服务、OAuth、相册扫描或自动分享。

## main 的实际规范

已查 `app/src/game/studio.js`、`services/studio-media.js`、`StudioWorkEditor.vue`、`StudioView.vue`：

- 标题60字、正文12000字、私语240字；作品最多4张图。已完成作品可以只有图片，但必须有标题和原任务记录。
- 选择PNG/JPEG/WebP，原图不超过20MiB。main保存的是缩小后的JPEG副本，依次尝试最长边1024/768/512和质量0.82/0.65/0.48；透明背景落在暖白纸色。单张data URL不超过240000字符，共享总预算1800000字符，容量不足不挤掉旧作品。
- PNG为1200×1600，首图加一页正文，省略图片或截断文字时标“作品选页”。HTML包含全部已完成作品的全部图片与正文，用户文字转义。私语默认不导出，仅本人明确勾选时加入。
- main本来就请用户另留原图；本轮不宣称压缩副本无损替代原文件。

来源：[作品模型](https://github.com/ThySummer14/kuangye/blob/764e83d95a48dbbe1cd4eff2b35cefc713acaf82/app/src/game/studio.js)、[图像与导出](https://github.com/ThySummer14/kuangye/blob/764e83d95a48dbbe1cd4eff2b35cefc713acaf82/app/src/services/studio-media.js)。

## 本轮可用闭环

作品集内直接新建“自己的作品”（沿用原own主题），无需为了导入图片编造观察。旧观察衍生作品保持原关联。选择本地图片→看到缩略图与数量→可移除/取消→保存→退出重开仍有完整副本→图文或仅图片作品可确认完成→书桌沿用已有陈列对象展示首图→PNG选页/完整HTML作品集。

本轮只接作品图片。观察图片、素材图片快照、其余主题练习以及剩余15章能力仍在后续清单。小说/实地求证章继续要求原文字证据，图片不会自动当作整本小说或现实访问证明；章记录标清为“完成时的文字证据”。

## 文件选择与隐私

| 平台 | 拟实现 | 边界 |
|---|---|---|
| Web | 小型自有JavaScriptBridge桥，用户点击触发HTML文件选择；只读取本次选择的File字节 | 不请求目录/持续文件权限；不用远端URL；取消/关闭页面使旧请求失效 |
| 原生桌面 | Godot FileDialog选文件，限定三种格式，关闭删除/建目录功能 | 只读用户所选文件；测试仅用云端原创QA目录；不触用户电脑 |
| Web导出 | 先生成预览/缓冲区，再由明确下载按钮调用download_buffer | 避免异步生成后丢失浏览器用户手势；一次只发一个下载请求，不冒称浏览器已写盘 |
| 原生导出 | FileDialog选择新文件目标，保留覆盖提醒，成功写入后才提示完成 | QA写新的独立文件，不覆盖用户文件；拒绝或写盘失败保留当前作品 |

Godot 4.6的FileDialog在Web不能访问宿主文件；官方JavaScriptBridge提供回调、字节缓冲转换与下载接口，回调引用需保持，下载可能被浏览器阻止。见[FileDialog](https://docs.godotengine.org/en/4.6/classes/class_filedialog.html)、[JavaScriptBridge](https://docs.godotengine.org/en/4.6/classes/class_javascriptbridge.html)。

整个导入/缩图/导出在设备本地执行。无图片上传、fetch/POST、相册遍历、第三方CDN或分析服务。保存缩小副本时剥离EXIF/GPS等元数据；JPEG、PNG、WebP方向单独处理并用原创方向样例核验。4.6.3的[JPEG解码源码](https://raw.githubusercontent.com/godotengine/godot/4.6.3-stable/modules/jpg/image_loader_libjpeg_turbo.cpp)未见EXIF方向处理，不能假定引擎自动旋正。

## 格式与内存预算

- 沿用20MiB原文件限制、每作品4图、每图240000/全部1800000字符的副本预算。
- 额外提议：解码前检查签名及头部尺寸，最长边≤8192，总像素≤1600万。RGBA解码约64MB，这是预算推算，不是性能实测；超过时拒绝并保留旧图，请用户先缩小。
- 仅静态PNG/JPEG/WebP；拒绝SVG、GIF、HEIC、动画PNG/WebP、外部URL、空文件、伪装/截断文件。不能只信扩展名或浏览器MIME。
- 一次只解码一张，先检查后分配大像素缓冲；缩到1024后释放大图，再尝试质量/更小尺寸。所有候选验证通过后才更新草稿，单批坏文件不覆盖旧图。
- 同一作品重复的规范化图片去重，不占第二份名额；不自动合并不同作品。关闭导入或换作品后，旧回调不能写入新作品。
- 预览使用小缩略图，避免把200件作品的原尺寸图片同时变成纹理。PNG离屏画布约1.92MP；导出后释放画布与缓冲。实测进程仍按≤1GiB硬限，无法满足则降低初始解码预算。

## 持久化与失败处理

副本完整data URL字节嵌入作品images字段，随JSON原子保存，不存blob URL、临时路径或外部资源地址。选择/移除先改会话草稿，明确保存后提交；取消不改已存作品。写盘失败保留可重试内存副本，在面板内显示未保存状态，重试不再发奖励，也不把旧图清空。

原型v4写独立文件，只在不存在v4时依次读现有v3、原v1/v2；旧文件不覆盖。已有v4就是迁入标记，损坏不静默回退。回退旧版后的新进度不会自动并入现有v4。新creative schema只开放work.images与own主题，旧schema仍按原规则检验；未知图片字段或预算超限整份拒读并保留文件。

章柜的冻结记录继续保存原文字证据，不在这一轮扩大为图片证据系统。图片容量按已有作品与未来观察/素材预算接口统一计算，当前后两类仍为空。不清网站存储，不要求新权限来“修复”容量错误。

浏览器user://依赖IndexedDB；私密模式、存储阻止或配额可能影响持久化，OS检测本身也不能保证。会真实重开验证并保留导出退路。见[Web持久化限制](https://docs.godotengine.org/en/4.6/tutorials/export/exporting_for_web.html#using-cookies-for-data-persistence)。本轮不宣称首次离线打开整个网站；独立HTML作品集可离线打开。

## 导出与验收

PNG遵循原尺寸/边距/首图选页逻辑，使用现有完整中文字体。HTML仅内嵌样式和经过验证的data图片，不执行脚本、不读外部地址；标题、正文、私语全部转义。默认私语关闭，每次导出明确选择。多图/长文PNG提示“作品选页”；HTML验证完整正文与全部图片，避免把一页卡片当完整备份。

分三小步，每步保存检查点：

1. 图片校验、规范化、模型与迁移：原创RGBA色块/透明PNG、方向JPEG、WebP、超尺寸头/坏文件；测试四图/总容量、重复/移除/取消、旧档/坏档、保存失败与重开字节一致。
2. 原生与Web选择/预览：真实选择原创QA文件，重开看到图片，检查晚到回调、移动安全区及中文输入不回归；在有界云端原生/浏览器窗口各留证。
3. 实际PNG/HTML导出：核PNG尺寸、图文不越界/截断标识、HTML图片字节完整/转义/默认私语缺席；原生实际写出文件，Web实际点击下载并检查收到的文件。浏览器阻止或设备未测时如实报告，不把调用成功当下载完成。

QA材料仅为原创测试图和虚构测试文字，不使用真实用户照片或聊天。重窗口按共享锁分段≤110秒、≤1GiB，临时QA文件预计≤100MB，保留7GiB盘余量。iOS/Android真实相册与分享仍需实机，不用桌面窗口代称手机通过。
