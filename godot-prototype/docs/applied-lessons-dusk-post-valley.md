# 暮邮谷经验在原 Godot 小镇线的落地（v7.5.2 候选）

来源：ThySummer14/dusk-post-valley PR #1（`cursor/exploration-polish-r6-a8cc`）的 `docs/lessons-for-kuangye.md` 及 r3–r5 修复。只作用于本分支 `godot-prototype/`；未使用 `godot/` 或 `godot-town-exploration` 线。美术、玩法、v4 存档结构与 v7.x 功能不变。

## 审计结论

| 方面 | 改前 | 结论 |
|------|------|------|
| 存档安全 | v4 先写 `.tmp`、回读校验再改名；严格结构校验；无法识别/更高版本即只读锁定；v3/v1 原文件保留 | 已达标，未改动 |
| 走位 | 不保存房间与位置，重开总在镇口 | 缺口 |
| 中断 | 失焦清触摸与路线；无网页 `visibilitychange/pagehide`；只靠焦点事件恢复小芽 | 缺口 |
| 键盘 | 轮询物理键；切后台丢失 keyup 时可能"松手还在走" | 缺口 |
| 触摸 | 单指所有权、取消、拖到按钮上已处理；旋转时手指不释放；摇杆按住时第二指点不到按钮（引擎只模拟第一指） | 缺口 |
| Web 安全区/密度 | 安全区只在原生移动端读取；Web 画布按设备像素绘制但 UI 密度固定 1 | 缺口：手机浏览器里 UI 极小、无摇杆 |

说明：本原型使用自己的 `town-prototype-v4/v3/v1.json`，不读写 Vue 应用的 `kuangye.v3`，相关语义保持不变。

## 已应用

1. **走位单独存档**：`user://town-prototype-v4-walk.json` 只存房间与坐标，不进 v4 主存档，旧版构建仍能读取 v4。写入同样经过 `.tmp`、回读校验和改名。损坏或未知内容直接忽略，不会阻断主存档。启动时只恢复可通行的位置；落在家具/景物里或室内出口踏板上时，回到默认入口。主存档被锁定时连这份也不写。
2. **记录时机**：停步 0.6 秒、进出房间、失焦、切后台、关窗、网页隐藏。Web 端 IndexedDB 要在下一帧才同步，而隐藏的页面可能不再出帧，所以"停步即记"才是可靠路径。
3. **统一中断**：失焦、`APPLICATION_PAUSED`、`WM_CLOSE_REQUEST` 和网页 `visibilitychange/pagehide` 都走同一套处理：释放手指与路线、记录走位、重试待保存的进度（锁定时不写）。网页回到前台时恢复小芽动作，不依赖焦点事件。
4. **键盘锁存**：中断时还按着的方向键，要松开一次才会再次生效。
5. **旋转/缩放释放手指**：视口尺寸变化时取消正在进行的摇杆或布置拖动（布置预览回到拖动前位置，与已有"取消"语义一致）。
6. **第二指点按钮**：摇杆按住时，另一根手指轻点「互动 / 随手记 / 重试保存」会生效；拖开或系统取消则不触发。先抬起摇杆手指也照常生效。
7. **Web 安全区与密度**：通过 `env(safe-area-inset-*)` 读取安全区并换算成画布像素；UI 密度按 `devicePixelRatio` 计算（原生桌面仍为 1）。Web 安卓/iOS 与原生移动端一样显示摇杆、隐藏键盘提示。
8. **竖屏才用定宽镜头**：宽度不足 760 的横屏手机（如 iPhone 横屏 750×342）改用定高取景，避免放得过大。

## 未应用及原因

- **关闭全局触摸转鼠标、全部换成自建 TouchButton/TouchScroll**：要改动所有面板的按钮与滚动，回归风险大。这次只处理 HUD 上的第二指；面板内多指问题留待真机反馈。
- **隐藏时 `canvas.blur()`**：桌面浏览器切回后键盘会失去焦点，要点一下画面才能操作。这里改为直接调用游戏内的中断处理。
- **中断时弹暂停菜单**：本作没有暂停菜单，也不希望打断；打开的面板和会话草稿原样保留。
- **跨页面关闭保存草稿**：按现有规则，草稿只在本次会话暂留，明确保存才写入本机。
- **gzip WASM 加载器与构建清单**：网页外壳不在本仓库，部署在仓库外进行，这次不涉及。
- **相机平面移动与像素对齐**：原本已实现。

## 验证分层

- 无图形测试：`python3 godot-prototype/tests/run_all.py`，共 22 组全部通过，新增 `interrupts` 组 41 项（走位读写与回退、锁定不写、网页隐藏/显示、键盘锁存、旋转释放、第二指、安全区换算、横竖屏镜头）。
- 云端 Chrome 软件渲染 WebGL2（SwiftShader），按项目现有 Web 预设临时导出，未提交、未部署：390×844@3x 下画布为 1170×2532，UI 按手机尺寸显示；IndexedDB 中写入走位、重载后恢复；隐藏期间按住的键不再走；旋转时拖着摇杆会停下；摇杆按住时第二指可打开随手记；无页面或控制台错误。iPhone 13 / Pixel 7 横屏和 1280×720 桌面截图已自查。
- **未在真实手机上验证**。Chrome 模拟器里安全区为 0，因此安全区只有换算单测。帧时间、发热、输入法、真机杀进程后的 IndexedDB 都没有覆盖。

## 手机验收清单

建议 iOS Safari 与 Android Chrome 各走一遍，竖屏、横屏都试：

- [ ] 首屏文字与按钮大小正常，左下有摇杆，右下有「随手记」
- [ ] 刘海或灵动岛、底部横条不遮挡标题、微光数和按钮（横屏两侧也要看）
- [ ] 拖摇杆走一段，停下等 1 秒，划掉标签页或杀掉 App 再打开：应回到相近位置
- [ ] 进小家后停一下再关页，重开仍在小家，从门口出来回到小家门前
- [ ] 拖着摇杆时旋转屏幕：小芽停下，不会自己继续走
- [ ] 拖着摇杆时另一指点「互动」或「随手记」：能打开
- [ ] 切到别的 App 再回来：小芽不乱走，呼吸动作恢复
- [ ] 布置模式拖家具时切后台或旋转：预览回到原处，家具不丢
- [ ] 旧存档：升级前的家具、小记、作品、章柜都在；回退到 v7.5.1 也能读取 v4
- [ ] 外接键盘或桌面：按住方向键切标签再回来，要松开重按才走

## 仍待处理（P1）

1. 真机验收上表，并记录机型、系统、浏览器版本。
2. 页面隐藏后被系统回收时，最后一次写入可能没有同步到 IndexedDB（引擎在下一帧同步）。目前靠"停步即记"兜底；如真机仍丢位置，再评估在 JS 端主动同步。
3. 需在 `viewport-fit=cover` 的外壳和刘海机上核对安全区。
4. iOS Safari 软键盘遮挡随手记输入框（需要 `visualViewport`）。
5. 面板内多指和滚动手感，视真机反馈决定是否引入自建触摸按钮。
6. 真机帧时间与发热（云端软件渲染约 200 ms/帧，不具参考价值）。
7. 以现有 gzip 加载方式部署到独立 owner-only 候选地址；稳定站保持不变。
