## 0. 产品基调（所有模块共同遵守）

- 旷野是"事件型挑战 + 可见成长"，不是日常打卡 App；新系统不得把它拉回打卡产品。
- 维持现有安全感设计：无断签惩罚、无放弃扣款、无倒计时焦虑、无绝版压力。
- 光经济不通胀：新奖励优先复用现有的光结算、微光、铭牌机制，新增发放通道必须给出预算与理由。
- v3 存档兼容是红线：新字段走既有清洗/迁移路径，不得静默丢失旧记录。
- 旷野 3D 地图是目前完成度最高、最满意的部分，一切新界面以此为最高视觉标准。

### 3.3 通用形象重设计（设计探索，先出概念图）

- 小芽是第一赛季的限定形象；未来会换赛季主题（如收获季），吉祥物需要**可换肤的通用形象**。
- 先出 3~4 个概念方向（图 + 四个表情小样），本人选定后再实现；不一定是"芽"的形态。
- 约束：与旷野画风共存（低饱和、木质、微光）；轮廓简单闭合、便于程序化形变；不依赖贴图。
- 赛季主题与吉祥物形态的关系要写进设计：换季换"皮"，不换情绪系统与互动骨架。

## 4. 任务系列系统（大纲确定，内容本人写）

- 定位：主线/支线是任务层级；"系列"是成就的收集册/图鉴分类，按触发逻辑与人生维度组织。
- 本人已定四类：
  1. **限时系列**：跟赛季时钟，本季可完成；错过不绝版，下季以变体回归。
  2. **阶段系列**：同一主题的递进难度阶梯。
  3. **1st 系列**：人生各种"第一次"，与现有"首次购买刻铭牌"机制呼应，完成即永久载入图鉴。
  4. （限时、阶段、1st 之外均由 Agent 评估补充，见下）
- Agent 从候选中挑选 4~7 类纳入大纲，候选池：累计、连续、收集/图鉴、组合、限制、无伤/完美、速度、难度分层、随机奇遇、隐藏彩蛋、探索、羁绊、社交、创造、技能树、习惯微行动、身份称号、资源经营、情绪记录、复盘记录、传承影响、反向（断舍离/反内卷）、元系列、周期循环、故事/角色、多人协作。
- 选择标准（按优先级）：
  - a) 与现有机制重合的**合并而非新造**：连续→并入现有打卡；技能树→并入五域属性；不得平行出现第二套同类系统。
  - b) 适合事件型挑战，不是日常重复。
  - c) 内容可持续：本人能亲手写出该系列首批任务而不枯竭。
  - d) 有"收集感"回报（图鉴条目/铭牌/蚀刻章），但发放规则复用现有光经济，不悄悄通胀。
- 每个被否决的候选须一句话说明理由。
- 与 3.3 联动的候选提示（供 Agent 评估时参考，不强制）：累计（人生尺度档案的成册化）、收集/图鉴、组合（五域同日各一件）、探索（直接落在地图区域解锁上）、周期循环（生日/节气，与赛季同频）、反向（与产品气质契合）、故事/角色（挂木木师傅与世界观 NPC 线）。
- 交付：`docs/SERIES.md` 设计文档 + `app/src/data/` 系列声明骨架（每类一个空模板）+ 待决问题清单。本轮不实现界面。

## 5. 成就与蚀刻章（本轮新增）

- **蚀刻章**：完成成就获得的一枚徽章，是系列/成就体系的收集载体。
- 每一枚蚀刻章都必须**精心设计**：刻蚀纹样、材质感、命名、背后的意义说明；拒绝模板化换色。
- **升级与镀彩**：更高难度或更高阶段的完成可以让同一枚章逐阶升级，最终形态为**镀彩**（彩蚀）。
  - 具体阶数、升级条件（难度 E–S？完成阶段系列的更高阶？赛季变体？）由 Agent 在大纲中给出方案，本人拍板。
  - 镀彩应是长期可见的荣誉终点，获取曲线克制，避免第一赛季就人手镀彩。
- 视觉基调建议往"蚀刻金属/木刻拓印"靠，与旷野的手作感统一；徽章展示需要一个图鉴性质的入口（按 1 的规则，入口应是地图上的建筑/场所，具体位置待系列大纲定）。
- 与现有系统的关系必须理清并写进文档：蚀刻章 vs 光（不直接兑换？）、vs 铭牌（记忆归铭牌、荣誉归章？）、vs 系列图鉴（章即图鉴条目？）。
- 本轮先出设计大纲（定义、获取规则、升级树、展示位、发放预算），徽章的美术实现走概念图先行的流程（同 3.3）。
