# App Store 发布准备

核查日期：2026-09-25。当前为 Web 一阶段交付并完成原生模拟器纵向原型；尚未制作签名包或提交审核。以下是技术决策和材料草稿，不代表审核通过或用户已确认定价。

## 技术路线

优先验证 Vue + three.js 的 Capacitor 本地打包：界面、模型和章资产随安装包提供，核心任务与小家离线可用，天气失败不阻断任务。先做纵向原型，再根据真机启动、内存、触控和后台恢复结果决定是否需要局部原生化。网站地址套进 WebView 不算完成；Apple §4.2 要求超出重新包装网站的实际价值。验收必须包含原生文件备份/恢复、系统分享、安全区、键盘、离线任务完整闭环和 WebGL 上下文恢复。[审核指南](https://developer.apple.com/app-store/review/guidelines/)

原生版已使用自研存档适配器，以 current/previous 双代原子文件保存完整 v3 状态和设置，读回校验后确认成功；没有引入 Preferences 插件或 SQLite。保留既有清洗与导入格式，首次迁移先复制、校验，不删除旧键。应用和 SDK 的 Privacy Manifest 分别随包提供。逻辑和模拟器验证见 [NATIVE-STORAGE](NATIVE-STORAGE.md)，不替代真机迁移验收。

建议首版研究一次性付费下载，减少交易机制干扰；价格和最终模式由用户决定。若改为应用内解锁数字内容，实施前按销售地区及当时 §3.1 规则核查 StoreKit/IAP；不出售光或荣誉，不以订阅续费维持用户历史。[Apple 审核指南](https://developer.apple.com/app-store/review/guidelines/)

## 商用前必须解决的天气边界

当前实时天气依赖 Open-Meteo。其免费端点用于非商业用途，商业订阅提供商业使用许可；天气数据署名义务与 API 使用权限是两回事。售卖版上线前必须选择：取消网络天气并保留本地时间/手动天气，或在用户批准费用后采用可商用服务。默认先验证不依赖付费天气的离线发行方案；不能把服务密钥打包在客户端，也不能为藏密钥擅自引入后端。没有引入其 AGPL 服务器代码。[官方价格与许可说明](https://open-meteo.com/en/pricing)

## 隐私政策草稿槽位（待事实审计与用户确认）

产品主体、支持邮箱、政策 URL、生效日期：待用户提供并确认。

任务进度、手记、家具和荣誉记录存于设备；目前没有应用账号、自己的业务后端、广告或行为分析 SDK。用户可以导出备份并自行保管；卸载或清理浏览器数据可能丢失未备份内容。原生“重置”删除 Application Support 中的 current/previous 两代存档，但刻意保留 Documents 中用户主动导出的备份。

天气启用时会向第三方发起请求；设备定位需授权，坐标和网络地址的数据流、服务方留存政策须另行核查，不能仅因“没有自己的服务器”就勾选“不收集数据”。Apple 的收集定义涉及离开设备且留存超出实时请求需要的情况，发布前逐项填写，需公开隐私政策 URL。[App Privacy Details](https://developer.apple.com/app-store/app-privacy-details/)
