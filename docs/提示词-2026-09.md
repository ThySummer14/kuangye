## 第一轮 · 确定执行批（删蹦跳 → 地图导航 → 木器铺 → 表情试验台）

```text
# 背景
这是「旷野」v3：Vue 3 + three.js 静态站点，无后端，localStorage 存档，现有顶部
导航条含今日任务/小芽的家/林间集市/成长手记等入口。本轮按顺序完成下面四件事。

# 工作方式（先定流程，再动工）
- 开工前先 git 提交一个干净基线；下面四件事每件完成并自查通过后单独 commit，
  任何一步都要可回退、可对比。
- 先给我一份执行计划（每件事打算怎么做、怎么验），我看一次、批了之后一口气
  执行到底，不要再逐步找我。
- 动手做功能之前先把检查手段建起来：扩展 game/webmcp.js（或等价的页面钩子，
  形如 window.__KUANGYE__），暴露当前场所、导航状态、情绪参数；为「地图导航、
  木器铺、表情试验台」各建一个可复放的具名测试场景，能一键回到起点、截图、
  读状态。
- 执行中把关键决定、走过的弯路和理由随手记进 docs/RUNLOG-2026-09.md，
  收工前沉淀成"下次该怎么做"。

# 1. 删除小芽蹦跳互动
现在点击地面小芽会寻路蹦跳，这个动作观感不好：整体移除 RoamingBuddy 的蹦跳/
游走表现，保留站立 idle 和表情（眨眼、呼吸、视线跟随）。相关动作等形象定稿后
另行设计。蹦跳/游走与房间互动的代码边界以实际仓库为准，你自行定位，
原则只有一条：只去蹦跳，不动房间互动（浇花、坐下、打盹、读书、摇摆）。

# 2. 地图成为唯一导航
我最满意的部分是旷野 3D 地图，后续所有界面入口都收进地图：移除页面顶部的
「旷野地图/今日任务/小芽的家/林间集市/成长手记」导航条，每个场所对应地图上
一个可点击的建筑或场所标签，点击进入对应视图；进入子页面后有轻量返回。
手机端同样以地图为入口，底部导航可以去掉或只留一个「回到地图」。
这是长期规则：以后所有新面板的入口都必须是地图上的建筑/场所，不得再提议
顶部导航。判断标准：任何功能从地图出发两击内可达，桌面与 375px 主路径无死路。

# 3. 装修师傅独立店铺
木木师傅不再出现在小芽的家里，在地图上给他加一栋「木器铺」建筑，点击进店。
整个店铺面板由你设计：扩建、换墙面、换地板都迁到店里办理；面板要像一家真实
作坊（陈列可购买的墙色/地板样本、扩建方向示意），风格与现有 3D 岛统一，
沿用现有价格与存档语义，不改变经济规则。家里的相应功能入口移除。

# 4. 表情系统重做（移植参考项目手感）
现在小芽的表情不好看、切换不自然。参考 ~/Downloads/bloub-main（同为 Vue3：
一个封闭形态在 14 种状态间 morph，眼睛是独立白色形态，可直接移植）和
~/Downloads/moodstone-master（React Native Skia：看它的 mood 定义与切换节奏、
弹簧参数，不移植代码）：把情绪切换重做成连续 morph + 弹簧插值，无跳变，
保留眨眼/呼吸/视线跟随。先在站外做一个独立的「表情试验台」页面：可以点选
全部情绪、预览任意两情绪间的过渡、调参数；试验台验收后再接回主站的
BuddyFace 与 3D 小芽，情绪参数仍以 game/emotions.js 为单一事实源。

# 完成定义（不满足就继续修）
- npm test 全绿、npm run build 成功；不破坏 v3 存档兼容，不新增光发放通道。
- 用开头建好的具名场景与页面钩子复放自查：导航、木器铺、试验台各截一组图
 （桌面 + 375px），截图与状态记录写进 RUNLOG，作为可追溯的交付证据。
- 自己看着别扭的观感问题（比例、间距、过渡生硬）主动迭代；"完成"= 四件事
  都在浏览器里跑通并留证，不是第一版实现后回来等审查。
```

## 第四轮 · 任务系列 + 蚀刻章大纲（只交文档与骨架）

```text
# 任务系列与成就系统大纲（本轮只交设计文档与骨架，不实现界面、不写具体任务）

## 背景
旷野已有：赛季（3个月）+ 月双层节奏、五域属性、连续打卡、光经济（完成结算+
微光）、家具铭牌记忆、成长手记。任务定位是"事件型挑战"，不是日常习惯打卡；
系列与成就系统不得把它拉回打卡产品，不得无断签惩罚、不得制造倒计时焦虑。

## 分工（重要）
具体任务文案全部由我本人撰写。你负责大纲和骨架：系列的定义、分类逻辑、
数据结构、进度判定、入口摆放、与现有系统的挂钩方式。

## A. 任务系列
我已确定三类，请为它们各设计完整定义与模板槽位：
1. 限时系列：跟赛季时钟走，本季可完成，错过不绝版、下季以变体回归；
2. 阶段系列：同一主题的递进难度阶梯；
3. 1st 系列：人生各种"第一次"，与现有"首次购买刻铭牌"机制呼应，完成即永久
   载入图鉴。
除上述三类外，从以下候选中挑选与旷野现有系统最契合的 4~7 类纳入大纲：
累计、连续、收集/图鉴、组合、限制、无伤/完美、速度、难度分层、随机奇遇、
隐藏彩蛋、探索、羁绊、社交、创造、技能树、习惯微行动、身份称号、资源经营、
情绪记录、复盘记录、传承影响、反向（断舍离/反内卷）、元系列、周期循环、
故事/角色、多人协作。
选择标准（按优先级）：
a) 与现有机制重合的合并而非新造——"连续"并入现有打卡、"技能树"并入五域
   属性，不得平行出现第二套同类系统；
b) 适合事件型挑战而非日常重复；
c) 内容可持续：一个赛季我能亲手写出该系列首批任务而不枯竭；
d) 有明确的收集感回报（图鉴条目/铭牌/蚀刻章），但奖励规则必须复用现有光
   经济，不得悄悄通胀。
每类入选与否决的候选都要给出理由，理由须能追溯到旷野现有机制或明确的产品
气质，不接受悬空的审美判断。

## B. 蚀刻章（成就徽章）
完成成就获得「蚀刻章」——一枚精心设计（注意：不是模板换色）的徽章，作为
系列/成就体系的收集载体；更高难度或更高阶段的完成可以让同一枚章逐阶升级，
最终形态为「镀彩」。请在大纲中给出：
1. 章与系列的映射：一章对应一个系列、一条阶段线还是一个成就节点？给出你
   的建议方案；
2. 升级阶梯：阶数与升阶条件（挂钩现有 E–S 难度？阶段系列更高阶？赛季变体？），
   并设计获取曲线——镀彩是长期荣誉终点，第一赛季不应人手一枚；
3. 与现有系统的边界：蚀刻章 vs 光（是否可兑换？建议不可，纯荣誉）、
   vs 铭牌（记忆归铭牌、荣誉归章？）、vs 图鉴（章即图鉴条目？）；
4. 视觉基调：往蚀刻金属/木刻拓印的手作感靠，与旷野 3D 岛统一；先给每阶
   的纹样方向描述，美术实现走概念图先行的流程，本轮不产出图；
5. 展示入口：图鉴性质的陈列位（按既定规则必须是地图上的建筑/场所，位置
   与形态在大纲中提案）。
发放预算：明确一个赛季正常游玩+认真完成大概可得几枚、几阶，论证不通胀。

## 交付物
1. docs/SERIES.md：每个入选系列的定义、判定规则、蚀刻章映射与升级树、与
   赛季/五域/光经济/NPC 的关系、界面入口建议；
2. app/src/data/ 的系列与蚀刻章声明骨架样例（每类一个占位模板，字段齐全、
   内容为空），说明新增字段与 v3 存档的兼容和迁移策略；
3. 待决问题清单：所有需要我拍板的分歧点（至少含：章的映射粒度、升阶条件、
   镀彩曲线、图鉴入口选址）单独列出。

## 完成定义
文档达到"我拿着它可以直接开写第一批任务、不需要再追问"的程度；不满足就
继续打磨。本轮不运行界面改动，npm test 保持全绿即可。
```
